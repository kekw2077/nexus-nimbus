# Nexus Nimbus

Настольный клиент Nextcloud для Windows. Собственный интерфейс в оформлении
Nexus вместо официального клиента — с одной главной идеей: **у каждого файла
виден недвусмысленный статус присутствия**, и никакой файл не появляется на
диске сам по себе.

## Статусы присутствия

| Значок | Состояние | Что это значит |
|---|---|---|
| ☁ | `remote` | Только на сервере, диск не занят |
| ⟳ | `transferring` | Прямо сейчас качается или заливается |
| ✓ | `cached` | Лежит в кэше, совпадает с сервером, можно вычистить |
| 📌 | `pinned` | Закреплён: автоочистка не тронет |
| ↑ | `dirty` | Локальную копию правили, на сервер не отправлено |
| ↺ | `outdated` | Локальная копия есть, но на сервере файл новее |
| ! | `conflict` | Изменилось и здесь, и там |

Раздел **«Локальное»** показывает всё, что реально лежит на диске, с размерами
и кнопкой «освободить место». В сайдбаре два одинаковых индикатора — сервер и
этот компьютер — чтобы их можно было сравнить взглядом.

## Как поставить

Готовый установщик — на странице
[релизов](https://github.com/kekw2077/nexus-nimbus/releases). Мастер спросит,
ставить только для вас (`%LocalAppData%\Programs\Nexus Nimbus`, без UAC) или
для всех (`Program Files`). На семейных машинах разумнее первое: тогда и тихие
обновления проходят без запроса прав.

Обновления приходят сами: приложение проверяет канал при запуске и раз в шесть
часов, скачивает подписанный установщик и предлагает поставить. Канал
переключается в настройках — GitHub или свой сервер. Порядок выпуска новой
версии — в [dist/README.md](dist/README.md).

При первом запуске — экран входа. Нужны адрес сервера, имя пользователя и
**пароль приложения** (Nextcloud → Настройки → Безопасность → «Устройства и
сеансы» → создать новый). Пароль от самой учётной записи приложению не нужен и
нигде не сохраняется. Кнопка «Войти через браузер» делает то же самое через
Login Flow v2 — сервер выдаёт пароль приложения сам.

Пароль хранится в Credential Manager Windows через `flutter_secure_storage`.
Для self-hosted с самоподписанным сертификатом есть галочка «Доверять
сертификату» — она ослабляет проверку только для указанного хоста.

### Точки Nextcloud, которые используются

| Что | Адрес |
|---|---|
| Файлы | `/remote.php/dav/files/{user}/…` |
| Чанковая загрузка | `/remote.php/dav/uploads/{user}/{id}` + `MOVE .file` |
| Миниатюры | `/index.php/core/preview?fileId=…&x=…&y=…` |
| Квота | `PROPFIND` корня, `d:quota-used-bytes` / `d:quota-available-bytes` |
| Корзина | `/remote.php/dav/trashbin/{user}/trash`, возврат — `MOVE` в `…/restore` |
| Профиль | `/ocs/v2.php/cloud/user` |
| Вход | `/index.php/login/v2` + опрос `poll` |

Свойства в `PROPFIND`: `getlastmodified`, `getcontentlength`, `getcontenttype`,
`getetag`, `resourcetype`, `oc:fileid`, `oc:size`, `oc:permissions`,
`oc:favorite`, `nc:has-preview`. `etag` и `fileid` сохраняются в индексе
хранилища — на них будет опираться двусторонняя синхронизация.

## Оформление

Токены, стекло, аврора, сетка точек и контролы перенесены из
`F:\flutter\mirai\test1\handoff` без изменения значений; классы переименованы
из `Evs*` в `Nx*`. Настройки темы, акцента, матовости, фона, сетки и анимаций
живут на экране «Настройки» и переживают перезапуск.

Одно отступление от прототипа: `BackdropFilter` стоит только на панелях
(сайдбар, карточки, диалоги). Строки файлового списка плоские — стекло на
каждой из двух тысяч строк съедает кадр целиком.

## Обновления

Полные подписанные установщики через WinSparkle (`auto_updater`). Два канала,
оба рабочие, переключаются в настройках:

| Канал | Куда смотрит | Когда удобнее |
|---|---|---|
| GitHub | `raw.githubusercontent.com/.../dist/appcast.xml` | по умолчанию, работает из любой сети |
| Свой сервер | адрес папки с `appcast.xml` | домашняя станция, без выхода наружу |

Переменная окружения `NIMBUS_UPDATE_FEED` перебивает оба — ей проверяют канал
перед выкладкой. Всё остальное — в [dist/README.md](dist/README.md).

## Облака

Подключается три, каждое своей учётной записью. Записей можно держать
сколько угодно, открыта всегда одна: переключение закрывает прежнюю сессию
и открывает новую, поэтому у каждой записи своё хранилище, своя
синхронизация и свои передачи.

| | Nextcloud | Яндекс.Диск | Google Drive |
|---|---|---|---|
| Протокол | WebDAV | REST API | REST API |
| Как входить | пароль приложения или браузер | браузер (OAuth) | браузер (OAuth) |
| Файлы, папки, передачи | да | да | да |
| Синхронизация и правка на месте | да | да | да |
| Корзина | да | да | нет |
| Миниатюры | да | да | нет |
| Публичные ссылки | да, с паролем и сроком | да, простые | нет |
| Версии, избранное, поиск по дереву | да | нет | нет |

Всё, чего у облака нет, интерфейс прячет: разделы бокового меню, пункты
контекстного меню и кнопку поиска. Кнопка, которая молча не сработает,
хуже отсутствующей. Что именно умеет каждое облако — в
[cloud_provider.dart](lib/core/models/cloud_provider.dart).

### Яндекс.Диск

**WebDAV у Яндекса больше не бесплатный.** Доступ по этому протоколу оставлен
подписке Яндекс 360; бесплатным записям сервер отвечает `402 Payment Required`
— и Яндекс Плюс тут не помогает, это разные подписки. Поэтому клиент ходит по
их REST API, который открыт всем. Заодно от этого выиграли: по REST есть
корзина, миниатюры и публичные ссылки, которых по WebDAV не было.

Плата за это — приложение надо один раз зарегистрировать:

1. [oauth.yandex.ru/client/new](https://oauth.yandex.ru/client/new) → создать
   приложение, платформа **«Веб-сервисы»**.
2. Права: **«Яндекс.Диск: чтение и запись»** (`cloud_api:disk.read`,
   `cloud_api:disk.write`) и **«Доступ к логину»** — логин нужен только затем,
   чтобы подписать запись в списке.
3. **Redirect URI не трогать** — подойдёт тот, что Яндекс подставил сам
   (`https://oauth.yandex.ru/verification_code`).
4. Скопировать идентификатор и пароль приложения в окно входа Nexus Nimbus.

Дальше вход в два шага: клиент отправляет в браузер, Яндекс после разрешения
показывает короткий код, и код переносится обратно в окно входа.

Лишнее действие здесь не по недосмотру. Яндекс выдаёт приложению постоянный
адрес возврата и сверяет с ним запрос; попросить возврата на локальный адрес
можно, только вписав его в настройки приложения, — а это поле в консоли
Яндекса доступно не всегда, и попытка кончается ошибкой 400 «redirect_uri не
совпадает с Callback URL». Схема с кодом работает у всех и без настроек.

Токен Яндекса живёт около года — повторять это придётся нескоро.

### Google Drive

К Диску нельзя войти паролем: такого протокола у Google просто нет. Пароли
приложений работают с почтой и календарём, но не с Диском. Единственная
дверь — OAuth, а он требует, чтобы **приложение было заранее
зарегистрировано**. Регистрация делается один раз, бесплатно:

1. [console.cloud.google.com](https://console.cloud.google.com) → создать проект.
2. «APIs & Services» → «Library» → включить **Google Drive API**.
3. «OAuth consent screen» → тип **External** → заполнить название и почту →
   добавить себя в **Test users**.
4. «Credentials» → «Create credentials» → **OAuth client ID** → тип
   **Desktop app**.
5. Скопировать идентификатор и секрет клиента в окно входа Nexus Nimbus.

**Про семь дней.** Пока приложение остаётся непроверенным («Testing»), Google
выдаёт разрешение на неделю — потом вход нужно повторить. Снять это можно
только публикацией, а полный доступ к Диску у Google «ограниченная область»:
её публикация запускает проверку вплоть до ежегодного аудита сторонней
фирмой. Для домашнего инструмента это несоразмерно, поэтому выбрана неделя.

**Документы Google — не файлы.** У Документов, Таблиц и Презентаций нет
содержимого, это записи в базе Google. Скачать их нельзя; в списке они без
размера, двойной клик открывает их в веб-редакторе.

## Чего пока нет

- **Своё сочетание клавиш.** Ctrl + Shift + N зашит; выбор своего требует
  записи нажатий и проверки, что оно не занято системой.
- **Отложенные копии не расходятся по машинам.** Расхождение остаётся
  местным делом того компьютера, где оно возникло.
- **Копирование папки целиком на Google Drive.** Drive не умеет этого одним
  вызовом, а обход дерева вручную стоил бы сотни запросов.

Всё остальное из прежнего списка написано — см. разделы ниже и
[STATUS.md](STATUS.md), где сказано, что из этого ещё не проверялось руками.

## Правка на месте

Двойной клик открывает файл системной программой. Пока файл открыт, за папкой
хранилища следит watcher: как только программа сохранила файл, изменения
уходят на сервер сами.

Событие файловой системы само по себе ничего не значит — редактор пишет файл
частями, а Word и Excel сохраняют во временный файл и переименовывают его на
место исходного. Поэтому watcher ждёт секунду тишины после последнего события,
сверяется с индексом хранилища (совпало — это следы собственной записи
клиента, а не правка) и проверяет, что файл не заперт редактором.

Автоотправку можно выключить в настройках — тогда вместо отправки появляется
предложение с кнопкой «Отправить». В обоих случаях файл помечается статусом
`dirty`, и отправить его можно из контекстного меню в любой момент.

## Синхронизация

«Держать локально» на папке — это подписка на обход, а не разовое скачивание.
Раз в несколько минут (интервал в настройках) клиент обходит закреплённые
папки — или всё дерево, если включено «Синхронизировать всё облако», — и
сводит их с сервером:

| Что нашли | Что делаем |
|---|---|
| Файл есть на сервере, у нас его нет | Качаем |
| Etag на сервере изменился, местная копия цела | Качаем |
| Местная копия изменена, на сервере — нет | Отправляем |
| Изменено с обеих сторон | Откладываем местную копию, качаем серверную |
| На сервере файла больше нет, местный не правили | Убираем местную копию |
| На сервере файла больше нет, местный правили | Возвращаем его на сервер |
| Новый файл появился в папке на диске | Отправляем, создав недостающие папки |

Про расхождения. Местная версия не выбрасывается: она переезжает в
`имя (конфликт 2026-09-06 14-30-12).ext` рядом с исходником, и на её место
встаёт серверная. Обе версии целы, а выбирать между ними — дело человека.
Отложенные копии остаются только на этом компьютере и на сервер не уезжают;
список расхождений виден в настройках и в боковой панели.

Наружу не отправляются временные файлы редакторов (`~$…`, `.~lock.…`, `.tmp`,
`.crdownload`), служебный мусор системы (`Thumbs.db`, `desktop.ini`,
`.DS_Store`) и сами отложенные копии.

Обходить всё дерево на каждом круге было бы неподъёмно, поэтому обход
опирается на etag папки: Nextcloud меняет его от любой правки внутри, включая
вложенные. Совпал с тем, на котором в прошлый раз сошлись, — в поддерево можно
не заходить. Etag запоминается только после круга, на котором по этой папке
не понадобилось ни одной передачи: иначе недокачанное поддерево осталось бы
пропущенным навсегда.

## Избранное, версии, ссылки и поиск

Всё четыре живут на сервере, а не у клиента, — значит, видны одинаково и здесь,
и в веб-интерфейсе.

| Что | Где | Через что |
|---|---|---|
| Избранное | раздел «Избранное» (Ctrl 2), звёздочка в списке | `PROPPATCH oc:favorite`, выборка — `REPORT` с `oc:filter-rules` |
| Версии файла | контекстное меню → «Версии файла…» | `PROPFIND` и `MOVE` по дереву `dav/versions/{user}` |
| Публичные ссылки | контекстное меню → «Поделиться ссылкой…» | OCS Sharing API, `shareType=3` |
| Поиск по серверу | Ctrl F или Enter в поле фильтра | WebDAV `SEARCH` (RFC 5323) |

Версии адресуются по `fileid`, а не по пути: переименование файла историю не
рвёт, а путь — рвёт. Поиск через `SEARCH` есть не на всякой сборке Nextcloud;
если сервер его не умеет, клиент говорит об этом прямо и предлагает фильтр по
текущей папке.

## Трей, автозапуск и горячая клавиша

Всё три выключены по умолчанию: программа, самовольно поселившаяся в
автозапуске и занявшая системное сочетание, — дурной тон, даже если она своя.
Включается в настройках, раздел «Трей и запуск».

Сворачивание в трей требует значка в трее — без него окно стало бы не достать,
поэтому один переключатель зависит от другого. Сочетание — `Ctrl + Shift + N`,
работает переключателем: окно на виду прячется, спрятанное показывается.

## Откат на прежнюю версию

Настройки → «Обновления» → «Показать выпущенные версии»: список читается из
того же канала, что и обновления, нынешняя версия помечена.

Установщик при этом **открывается в браузере, а запускает его человек**. Это
не недоделка: подпись установщика проверяет WinSparkle, и он же умеет ставить
только самое новое. Скачать и выполнить прежнюю версию своими руками значило
бы обойти проверку подписи, ради которой в проекте и заведён ключ.
